## 2. 三档定义

### 2.1 Basic（基础档）

> **目标：任何人能启动、能操作、能看清"我在被谁打"。**
> 不新增系统，只补齐"不补就没法玩"的缺口。

| 要求 | 内容 |
|---|---|
| 输入 | 全部核心动作用键必须可重映射；必须有冲突检测与提示 |
| 视觉 | FOV 可调；亮度可调；UI 至少有 1 档放大 |
| 听觉 | 主音量 / 音效音量独立；无音频时所有关键状态（低血量、被击中方向、撤离点到达）必须有视觉冗余 |
| 呈现 | 不做"仅凭颜色"传达关键信息（命中分级、稀有度、敌人等级） |
| 工作量估算 | **M（中，约 3–5 人日）** |

### 2.2 Standard（标准档）★ 建议档位

> **目标：有明确障碍的玩家可以完整通关，不牺牲体验深度。**
> 包含 Basic 全部要求，外加下面 9 条特性矩阵的完整实现。

| 要求 | 内容 |
|---|---|
| 全部 Basic | — |
| 色盲 | 3 档模式（Protanopia / Deuteranopia / Tritanopia）+ 形状/图标冗余 |
| 字幕 | 环境与战斗关键音效的文字提示（不是对话字幕，本作无配音） |
| UI 缩放 | 2 档（100% / 130%），覆盖 HUD + 库存 + 菜单 |
| 镜头晃动 | 3 档（100% / 50% / 0%），影响 bob + shake + recoil 视觉量 |
| 闪光敏感 | 3 档（正常 / 减弱 / 关闭），影响枪口照明、Bloom、未来闪光弹 |
| 难度 | 在 Normal / Hard 之外增加"辅助调节"项（敌人伤害倍率、搜索速度） |
| 工作量估算 | **L（大，约 10–15 人日）** |

### 2.3 Comprehensive（完整档）

> **目标：符合主流 3A 无障碍规范（对标 TLOU2 / Forza 级别）。**

| 要求 | 内容 |
|---|---|
| 全部 Standard | — |
| 完整重映射 | 键鼠 + 手柄 + 单键模式（长按转切换、连续开火转切换） |
| 屏幕阅读器 | HUD 语义化（`role` / `aria-live`），关键状态可朗读 |
| 视觉辅助 | 高对比度主题（第 3 套 UI 皮肤）、准星样式选择、色盲之外的"轮廓高亮"（敌人描边） |
| 认知辅助 | 可关闭的计时压力（练习模式）、无时间限制的搜索、导航辅助线 |
| 运动辅助 | 瞄准辅助强度分档、自动换弹、自动拾取 |
| 工作量估算 | **XL（15 人日以上，且需要 HUD 重构 + DOM 语义化，与"无构建原生 JS"架构有明显摩擦）** |

### 3.1 【A11Y-01】色盲

**现状问题（三个具体点）**

1. **稀有度完全靠颜色**：六档稀有度（common 灰 / uncommon 绿 / rare 蓝 / epic 紫 / legendary 橙 / ultimate 红）在 CSS（`index.html:32-37`）与 3D（`item_models.js:639-642`）里只体现为色相。
   **Epic 紫 `#9c27b0` 在 `#221a32` 背景上对比度只有 2.64:1**，连 WCAG AA 大字（3.0:1）都不达；在红绿色盲眼中紫/蓝/灰三档几乎同色。
2. **命中分级靠颜色**：普通白 / 爆头 `#ffc107` / 击杀 `#f44336`（`index.html:340, 345, 347`）。红绿色盲无法区分爆头与击杀。
3. **敌人受击变红**：`enemy_ai.js:151` `body.material.color.setHex(0xff6666)`。

**Standard 档要求**

| 信息 | 不能只靠颜色 → 必须叠加 | 具体做法 |
|---|---|---|
| 稀有度 | **形状/角标** | 每个稀有度在格子**左上角**加一个符号：common `·` / uncommon `▪` / rare `◆` / epic `★` / legendary `★+光晕` / ultimate `✦`。符号永远用 `--text-primary` 白色，不随色盲模式变 |
| 命中分级 | **几何差异** | 已部分存在：爆头线宽 3px 高 10px、普通 2px 高 8px（`index.html:347`）。**再加**：击杀时四条线外扩并追加一个 2px 外环；爆头追加中心点 |
| 敌人等级 | **轮廓线** | 等级 3 敌人加 1 px `0xff9800` 边缘光（复用现有 emissive 通道，不加灯） |
| 色盲滤镜 | 全屏后处理 | 在 `GradeShader` 后追加一个 3×3 色相旋转矩阵 pass（Protanopia / Deuteranopia / Tritanopia），`RenderPipeline` 内可直接加，CPU 成本为零 |

> 滤镜只做"补正"，**不能替代形状冗余**——滤镜是治标，冗余才是治本。

### 3.2 【A11Y-02】字幕 / 听觉信息文字化

本作**没有配音、没有对话**，因此"字幕"在这里的正确形态是**声音事件字幕**（Sound Captions），这是 FPS 里价值最高的一类无障碍特性——听障玩家靠它获知"背后有人换弹"。

| 事件 | 文案 | 优先级 | 屏幕位置 |
|---|---|---|---|
| 敌人在 15 m 内开火 | `⚡ 枪声 · 右后` | 高 | 准星下方 60 px |
| 敌方换弹 | `↻ 换弹声 · 近` | 高 | 同上 |
| 脚步（≤ 8 m） | `👣 脚步 · 左` | 高 | 同上 |
| 投掷物落地 | `⚠ 手雷 · 前方` | **极高**（生死信息） | 准星正下方，红色 |
| 治疗完成 / 被打断 | `✚ 治疗完成` / `✖ 治疗被打断` | 中 | 屏幕下方血条旁 |
| 撤离点进入 / 倒计时 | `🚁 撤离点 · 已进入` | 高 | 顶部 |
| 空投落地 | `📦 空投 · 东北 120 m` | 中 | 罗盘条（复用 `hud_feedback.js` 标记） |

**规范**：最多同时 3 条，新条目顶掉最旧；每条存活 2.5 s；方位词只用 8 向（前/前右/右/右后/后/左后/左/前左），不用角度数字。

### 3.3 【A11Y-03】UI 缩放

现状全程 px 硬编码（背包格 26 px、快捷槽 48 px、菜单 20–48 px），**没有任何一处可缩放**。

**Standard 档方案（成本最低）**

1. `html { font-size: 16px }  →  [data-ui-scale="130"] html { font-size: 20.8px }`
2. 把 `index.html` 中**字号**型 `px` 改为 `rem`（约 120 处），**尺寸**型（格子边长、槽位宽高）改为 `em` 并挂在同一个根字号上。
3. UI 缩放**不影响 3D canvas**，也不影响准星绝对定位（准星保持屏幕中心）。

**验收标准**：130% 下背包 6×16 格面板不溢出 1280×720 视口；HUD 四角元素不互相遮挡（现状已有 `ui_occlusion.png` 类截图可作回归基线）。

**两个必修项**

1. **Epic 紫 `#9c27b0` → 建议 `#b44be0`**（对比度 2.64 → 5.4 : 1，色相不变，仍能被识别为"紫"）。需同步改 `index.html:35` 与 `item_models.js:641` 两处。
2. **命中标记 vs 亮天空**：HUD 是浮在 3D 画面上的，背景不可控。**方案：给所有命中标记线条加 1 px 纯黑外描边**（`text-shadow` 的思路用在 `border` 上：`outline: 1px solid rgba(0,0,0,0.85)` 或加一层 `filter: drop-shadow(0 0 1px #000)`）。现已有 `box-shadow 0 0 3px`，在 2 px 细线 + 3 px 阴影下边缘仍不够硬，建议**阴影收紧到 1 px 且全黑**。

**亮度 / 对比度的实现缺陷**

现状把 `brightness/contrast` 做成 canvas 的 CSS filter（`settings.js:433-438`）：
- 与后处理链里的 ACES + `GRADE.contrast 1.06` **叠加**，玩家拉到 1.5 会变成双重提对比，天空直接爆白；
- CSS filter 会强制额外合成层，低端设备有成本（代码注释已意识到这点）。

**建议**：把"对比度"接到 `GradeShader` 的 `uContrast`（`render_pipeline.js:404`）而不是 CSS filter；CSS filter 只保留 `brightness`（当作后处理 fallback 时的兜底）。这样 UI 不受影响、只影响 3D 画面，语义也更正确（"画面亮度/对比度"而非"整个网页"）。

### 3.5 【A11Y-05】动态模糊

**本作管线无动态模糊 pass**（`render_pipeline.js` 后期链 = RenderPass → Bloom → Grade → FXAA，共 4 个 pass）。这本身是最优解：动态模糊是 FPS 里最主要的运动病诱因之一。

**要求**：申请任何"电影感"新 pass（motion blur / DOF / 强镜头畸变）时，**必须同时提供关闭开关，并默认关闭**。这条写进管线准入规则。

另外需要警惕一个"事实上的动态模糊"：**自适应分辨率**（`render_pipeline.js:621-646`，帧率 < 48 时按 0.1 步长降 DPR，下限 0.55）。DPR 从 1.5 降到 0.55 时画面会明显变糊，观感类似动态模糊且**不可预测**。建议在 Standard 档把它归入"画面稳定"类设置，并在 UI 上说明"低帧率时画面会自动变糊"。

### 3.6 【A11Y-06】镜头晃动

现状三个独立来源，**全部固定值、不可关**：

| 来源 | 参数 | 位置 |
|---|---|---|
| 相机位移抖动 | `camera.position.x/y` 位移，`_shakeDecay 0.88`，`amount × 2` | `animation_enhancement.js:76-90` |
| 后坐力俯仰 | `_recoilPitch` 上限 **0.2 rad = 11.5°** | `:112` |
| 后坐力偏航 | `_recoilYaw` 上限 **±0.1 rad = 5.7°** | `:113` |
| 后坐位移 | `_recoilKick` 上限 **0.08 m** | `:114` |

**Standard 档要求：3 档，乘算而非关闭功能**

```
A11Y.motionScale = 1.00 / 0.50 / 0.00
```

| 档位 | 相机抖动 | 后坐力视觉 | **后坐力机制** | 走路 bob |
|---|---|---|---|---|
| 100% | ×1.00 | ×1.00 | **不变** | ×1.00 |
| 50% | ×0.50 | ×0.50 | **不变** | ×0.50 |
| 0% | ×0 | ×0 | **不变（弹道扩散保留）** | ×0 |

> **关键设计原则：只减"视觉位移"，不减"机制后果"。** 后坐力是玩法平衡的一部分（连射必须抬枪），关掉视觉晃动不能让玩家获得更稳的枪。因此 `motionScale` 只能乘在 `camera.position` / `camera.rotation` 的视觉量上，**绝不能乘在弹道计算或 `_recoilPitch` 的瞄准偏移上**。这一点必须在实现时写注释锁死。

**验收**：0% 档下连续点射 30 发，屏幕中心像素位移 ≤ 2 px。

### 3.7 【A11Y-07】闪光敏感

**风险点**

| 风险 | 现状参数 | 说明 |
|---|---|---|
| 枪口闪光点光 | `PointLight(0xffc070)`，`intensity 6.5 × big`（霰弹/狙 ×1.5 = **9.75**），`distance 12` | 连发武器 10 发/秒 → **每秒 10 次强光脉冲**。WCAG 2.3.1 的红线是"任何 1 秒内闪烁不超过 3 次" |

### 3.8 【A11Y-08】键位重映射

现状已可用（15 个动作）。Standard 档补齐两项：

1. **冲突检测**：绑定时若新键已被占用，提示 `"该键已绑定到「换弹」，是否替换？"`。当前完全没有这段逻辑。
2. **双套预设**：`默认`（现 DEFAULTS）/ `左手`（WASD → IJKL，Shift → 右Shift，Ctrl → 右Ctrl，F → 右Shift 冲突需重排）。

**已知可用性缺口（不属于无障碍但是同一类）**：`README.md` 写 `G` 使用医疗包，而 `settings.js` 默认是 `Digit5/6/7` 三键。**文档与设置不一致**，玩家按 G 无效。需澄清。

### 3.9 【A11Y-09】难度选项

现状两档（Normal 1200 s / Hard 900 s，敌人 +40% HP、+50% 伤害、+25% 速度）。**Hard 是"提高挑战"，不是"降低门槛"**——对可访问性而言这是个空档。

**Standard 档要求：在模式之外增加"辅助调节"（Assist），独立于 Normal/Hard**

| 辅助项 | 档位 | 说明 |
|---|---|---|
| 敌人伤害倍率 | 1.0 / 0.75 / 0.5 | 直接作用 `enemy.damage`，不动 HP |
| 搜索速度 | 1.0 / 1.5 / 2.0 | 搜索容器耗时缩短，对高认知负荷玩家友好 |
| 撤离倒计时宽限 | 0 / +60 s / +180 s | 加在 `gameTime` 上 |
| 自动换弹 | 开 / 关 | 现有 `gameplay.autoReload` 已是 `true`（`settings.js:51`） |
| 瞄准辅助（Comprehensive） | 0–100% | 本项目不做，标注为未来项 |

> **原则**：辅助调节**不降低敌人 AI 的战术性**（不关敌人视野、不降命中），只降低"惩罚强度"与"时间压力"。这样既照顾可访问性，又不破坏搜打撤的核心张力。

## 4. 本项目建议档位：**Standard**

### 4.1 三条理由

**理由一：已有设置系统把 Standard 的边际成本压到了最低。**
`settings.js` 已实现完整的设置面板框架、`localStorage` 持久化（键 `fps_game_settings`）、`onSettingChange()` 实时应用、`applySettings()` 统一分发。Standard 档的 9 项特性里，**有 4 项（键位重映射、音量、FOV、画质）已经存在**，2 项（镜头晃动、闪光敏感）只需要在已有参数上乘一个系数（改动量各 2–10 行），真正的"新系统"只有色盲滤镜、声音字幕、UI 缩放三项。

**理由二：浏览器 FPS 的玩家基数包含大量"低配置 + 低端设备"用户，本来就处于可访问性弱势。**
项目明确支持 `SwiftShader` / `llvmpipe` 软件渲染（`performance_guard.js:43-52`），这意味着会有一批"帧率 20 fps、画面降采样到 0.55 DPR"的玩家——他们已经在视觉可读性上吃亏，色盲模式、UI 缩放、镜头晃动关闭对他们的价值远高于对高端玩家。

**理由三：Comprehensive 与当前架构有硬摩擦，投入产出比不合理。**
HUD 全部是 `position: fixed` 的裸 `<div>` + emoji，没有语义化、没有组件化、没有构建步骤。要做屏幕阅读器就得先重构整个 HUD DOM，这与"双击 `index.html` 就能玩"的核心卖点直接冲突。**建议明确写入产品决策：本项目不做屏幕阅读器支持**，并在商店页/开始界面诚实标注支持范围（这是行业通行做法，比"做了但不好用"更负责）。

### 4.2 落地路线图（三阶段，按投入产出比排序）

| 阶段 | 内容 | 特性编号 | 估算 | 依赖 |
|---|---|---|---|---|
| **P0（性价比最高，先做）** | ① 镜头晃动 3 档（`motionScale`）② 闪光敏感 3 档（`flashScale`）③ 键位冲突检测 ④ Epic 紫改 `#b44be0` ⑤ 命中标记加黑描边 | A11Y-06, 07, 08, 04 | **S–M（3–4 人日）** | 无 |
| **P1（差异化明显）** | ① 稀有度形状角标（不依赖颜色）② 色盲滤镜 pass（接在 `GradeShader` 后）③ UI 缩放 2 档（px → rem/em）④ 对比度改为接 `uContrast` | A11Y-01, 03, 04 | **M–L（6–8 人日）** | P1-③ 需 `index.html` 大范围替换 |
| **P2（体验完整）** | ① 声音事件字幕模块 ② 难度辅助调节 4 项 ③ 左手键位预设 | A11Y-02, 09, 08 | **M–L（5–7 人日）** | P2-① 需 `audio_engine.js` 暴露事件钩子 |

**P0 的 3–4 人日投入能覆盖本作风险最高的两项（镜头晃动、闪光）**，这是最该先做的部分。

### 4.3 必须在开始界面标注的支持范围（诚实声明）

> 本作支持：全部键位重映射 · 3 档镜头晃动 · 3 档闪光减弱 · 色盲模式 · UI 缩放 · 声音事件字幕 · 辅助难度调节
> 本作不支持：屏幕阅读器 · 手柄 · 全流程键盘操作（第一人称瞄准需要指针设备）
