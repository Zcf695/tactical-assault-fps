> **行号随版本漂移，不可作为唯一标识。** 本规格引用代码位置时优先写 `函数名()` 或特征串（如 `CONTAINER_TYPES.safe.items`），行号仅作辅助并标注「≈」。工程侧检索时请用函数名 / 特征串，不要依赖行号。

## 0. 分类口径（写作与验收的前提）

主理人已抽验 D-04，确认「`searchTime` 写了但从不被消费」属于**功能缺失**，不是数值偏弱。两类问题的验收方式完全不同，本文所有条目强制标注类别：

| 类别 | 定义 | 验收方式 | 本文条目 |
|------|------|----------|----------|
| **🔧 未实现** | 代码里没有生效路径，玩家身上观察不到该机制 | 必须**先能观察到机制存在**，才能谈数值。判据形式：「做了 X 动作，应看到 Y 现象」 | FIX-01/03/04/06/07/12/13/14/15 |
| **⚖️ 数值失衡** | 机制生效，但数值超出设计区间 | 机制已在跑，只调参数。判据形式：「某数值应落在 [a,b]」 | FIX-05/08/09/10/11 |
| **🧹 卫生** | 死代码 / 死字段 / 误导性声明 | 静态检查：`rg` 无引用 | DF-01～DF-12 |

> **禁止混用**：不得用「调数值」的方式关闭 🔧 类条目（例如靠提高 `searchSpeed` 技能来「修」搜刮前摇——那个技能本身也没生效）。

### FIX-01 🔧 出生点与撤离点分离

- **现象**：`map/military_base.js:559` 出生 (0,−135)，`map/military_base.js:303` 南撤离点 (0,−145)，**直线 10m**。密林（`forest_outpost.js:386` vs 撤离 (0,−135)）与工业港（`industrial_port.js:359` 同）均为 **5m**。开局 1 秒可站进撤离圈，8 秒完成撤离，全程零风险。撤离点全部位于地图边缘（|x| 或 |z| ∈ 125–145，地图半边 150）。
- **目标值**：
  - 任意出生点 → 最近撤离点 **直线距离 ≥ 90m**
  - 禁止「直线同侧」：出生点与最近撤离点不得在同一轴上（如都在 x=0）
  - 至少 1 个撤离点位于距地图中心 ≤ 100m 处（制造「深入才能快速撤」的取舍）
- **改哪里**：
  - `map/*.js` 的 `playerSpawn` 与 `extracts` 两组数组。建议方案：出生点内移至 `z ≈ −60`（三图统一），南撤离点外移至 `z = −150`，则距离 **90m** 达标；并把「发电站铁路撤离」`(−135,125)` 一类远点作为唯一远端保留。
  - 无需改 `game.js`。`spawnExtractPoints`（`game.js:6952`）从 `FIXED_EXTRACTS` 读取，自动生效。
- **验收判据**：
  1. 进入每张图，用全图（`M`）确认出生点与最近撤离点分居两侧，肉眼距离 ≥ 1/5 地图边长。
  2. 控制台：`Math.hypot(MAP_DATA.playerSpawn.x-e.x, MAP_DATA.playerSpawn.z-e.z)` 对 8 个撤离点取最小值 **≥ 90**。
  3. 开局后不移动，按住 `F` **不应**触发撤离（因不在半径 3.5 内）。
  4. 从出生点走到最近撤离点按 8 m/s 计时，**≥ 11 秒**。
- **优先级**：**P0**（这是搜打撤体验成立的地基）

### FIX-03 🔧 敌人数量上限（`enemyCount` 死字段）

- **现象**：三图声明 `enemyCount {normal:50/42/48, hard:75/65/72}`（`military_base.js:16`、`forest_outpost.js:14`、`industrial_port.js:13`），`loadMapData` 写入 `CONFIG.enemyCount`（`game.js:1238`），`spawnEnemies` 按此循环（`game.js:3416`）。但 `createEnemy` 在 `game.js:3438` 被硬卡：`if(enemies.length >= (isHard?CONFIG.maxEnemiesHard:CONFIG.maxEnemies)) return;`，而 `CONFIG.maxEnemies = 14 / maxEnemiesHard = 24`（`game.js:190-191`）。**三图实际都是 14/24，敌人维度零差异化**。300×300 = 90,000 m²，单敌覆盖 6,429 m²，等效间距 **80m**，而发现半径仅 28m。
- **目标值**（每图上限，考虑 60fps）：

  | 地图 | 常规上限 | 高危上限 | 理由 |
  |------|---------|---------|------|
  | 军事禁区 | **28** | **44** | 建筑最密（145 栋）、容器最多（170），需要最多威胁；300×300 下间距降至 57m，仍在发现半径 2 倍以上，避免开局贴脸 |
  | 工业港 | **24** | **38** | 开阔地形、掩体少，敌人效率最高，数量应低于军事禁区但高于密林 |
  | 密林前哨 | **20** | **32** | 树木遮挡多、视线短，同数量下威胁感知更强，故数量最低 |
  | 单敌覆盖面积（军事/常规） | 3,214 m² | — | 等效间距 57m |
  | 单敌覆盖面积（密林/常规） | 4,500 m² | — | 等效间距 67m |

  > **性能前置条件**：`maxEnemies` 是 `createEnemy` 的硬上限，也是 `updateEnemies` 每帧遍历的对象数。当前 14 个 AI 的 JS 开销未测量（D-12 无基线）。**上调前必须先跑 `?perfdebug=1` 记录 14→20→28→44 四档的 `js` 毫秒值**，若 44 档单帧 JS > 6ms（16.7ms 预算的 36%），则高危上限封顶 32。
- **改哪里**：
  - `game.js:190-191` → 删除全局 `maxEnemies/maxEnemiesHard`，改为接受地图级上限：在 `loadMapData`（`game.js:1227`）中增加 `CONFIG.maxEnemies = MAP_DATA.enemyCount.normal; CONFIG.maxEnemiesHard = MAP_DATA.enemyCount.hard;`
  - `map/*.js` 的 `enemyCount` 改为上表值（**这是让死字段变活字段的关键一步**）。
  - `game.js:7272` 高危增援的 `maxE=CONFIG.maxEnemiesHard` 自动跟随，无需改。
- **验收判据**：
  1. 三图各进一局常规，控制台 `enemies.length` 在 15 秒内稳定到 **28 / 20 / 24**（±2，受生成失败重试影响）。
  2. 高危进图，`enemies.length` 上限达 **44 / 32 / 38**。
  3. `rg "maxEnemies" game.js` 结果中**不再出现 `14` 与 `24` 字面量**。
  4. `?perfdebug=1` 下高危 44 敌时 `js` ≤ 6ms。
- **优先级**：**P0**（14 个敌人使常规模式接近无战斗搜刮模拟器）

### FIX-04 🔧 容器数量与密度统一（`containerCount` 死字段）

- **现象**：三图声明 `containerCount {normal:200/180/190, hard:260/240/250}`（`military_base.js:17` 等），**`spawnContainers`（`game.js:4997`）只遍历 `FIXED_CONTAINERS` / `HARD_MODE_CONTAINERS` 数组，从不读 `containerCount`**。实测数组长度：军事 **170**（高危 +26=196）、密林 **86**（+26=112）、工业港 **78**（+20=98）。军事实测是工业港的 **2.18 倍**，而局时长、撤离点数、地图面积完全相同 → 工业港单局收益期望约为军事禁区的 46%。
- **目标值**（统一口径：**每图常规容器数 140–170，高危额外 +20~26**；密度按「每 1,000 m² 容器数」对齐）：

  | 地图 | 现有常规 | **目标常规** | 目标高危总数 | 密度（每千 m²） | 需补充 |
  |------|---------|-------------|-------------|----------------|--------|
  | 军事禁区 | 170 | **170**（不变） | 196 | 1.89 | 0 |
  | 密林前哨 | 86 | **150** | 176 | 1.67 | **+64** |
  | 工业港 | 78 | **160** | 180 | 1.78 | **+82** |

  > **为什么不是全部拉到 170**：密林与工业港的建筑数只有 113（军事 145），容器/建筑比拉到 170 会变成 1.5，出现「建筑里塞 2 个箱子」的拥挤感。150/160 使其容器/建筑比落在 1.33–1.42，接近军事的 1.17，同时把收益差压到 **6–12%**（目标 ≤15%）。
- **改哪里**：
  - `map/forest_outpost.js` 的 `containers` 数组 **+64 条**；`map/industrial_port.js` **+82 条**。逐条给出 `{type, x, z}`，坐标须落在建筑群附近且不与现有容器重叠（`spawnContainers` 有 3.5m 去重逻辑，`game.js:4997` 内 `MIN_CONTAINER_DIST`）。
  - `map/*.js` 的 `containerCount` 字段**删除**（它是死字段，留着只会再骗一次人）。
  - **不要**改 `spawnContainers` 去读 `containerCount` —— 那会让容器变成随机撒点，失去关卡手工摆放的意义。
- **验收判据**：
  1. 控制台 `containers.length`：军事 **170**、密林 **150**、工业港 **160**（常规）；高危分别 **196 / 176 / 180**。
  2. `rg "containerCount" game.js map/*.js` **无结果**。
  3. 三图各跑一次「只沿着地图边缘搜 20 箱」的模拟，取出期望值，**极差 ≤ 15%**。
  4. 目视检查新增容器未穿墙、未落水（`spawnContainers` 的推离逻辑会兜住，但会破坏布局意图）。
- **优先级**：**P0**（选图决策当前失效）

- **目标值**：`非洲之星` 从 `safe.items` 与 `premiumBox.items` **移除**，改为独立「头奖掷骰」（jackpot roll）：
  - `safe`：**0.2%** 每箱
  - `premiumBox`：**0.4%** 每箱
  - 空投（`searchAirdrop`）与 BOSS 战利品池保留（它们本就该是顶级产出）
  - 期望效果：约每 500 个保险箱 / 250 个高级箱出现 1 次 → 一个专注玩家约 **15–25 局**见一次
- **改哪里**：
  - `game.js:625-628`：从 `safe.items` / `premiumBox.items` 字面量中删除 `'africa_star'`。
  - `game.js` 新增 `JACKPOT_TABLE = { safe: 0.002, premiumBox: 0.004, airdrop: 0.02 }`，并在 `createContainer`（生成容器物品后）追加一次独立掷骰，命中则 push 一件 `africa_star`。

  1. 连开 200 个保险箱，`africa_star` 出现次数 **0–3 次**（期望 0.4）。

### FIX-16 🔧 超时改为「弃包撤离」（**主理人 Q-01 已裁定**）

- **现象**：`updateTimer()` 内 `if(remain<=0) endGame(false);`（≈`game.js:7259`）——**超时与阵亡走完全相同的分支**。结算标题、损失规则、XP 全都是「行动失败 / 阵亡」，玩家在撤离点外被时间杀掉，和被打死惩罚一样。这抹掉了「差一点就撤出去」的遗憾美学，也没有给出「最后一分钟」的决策点。
- **裁定结果**：**引入第三结局**。口径固定为：
  > 撤离倒计时归零 → 判定为**撤离成功**，但**背包内物品全部丢失**，仅保留**安全箱 + 口袋内物品**。
- **目标值**：`endGame` 需要支持第三态。三种结局的损失规则：

  | 类别 | 撤离成功 | **超时（弃包）** | 阵亡 |
  |------|----------|----------------|------|
  | 资金 | `+= lootValue` | **`+= 残留 lootValue`（仅安全箱+口袋部分）** | 不变 |
  | 安全箱 | → 仓库 | **→ 仓库** | → 仓库 |
  | 口袋 | → 仓库（FIX-10 修后） | **→ 仓库** | 丢失 |
  | 钥匙链 | 保留 | **保留** | 保留 |
  | 背包内物品 | → 仓库 | **丢失** | 丢失 |
  | 胸挂内物品 | → 仓库（FIX-10 修后） | **丢失** | 丢失 |
  | 武器 / 护甲 / 头盔 / 胸挂 / 背包 | → 仓库 | **丢失** | 丢失 |
  | 结算标题 | 撤离成功 | **弃包撤离** | 行动失败 |
  | XP | 正常公式 | **按残留 lootValue 计** | 0 |

- **改哪里**：
  - `updateTimer()`：`endGame(false)` → **`endGame('timeout')`**（改为字符串三态，或 `endGame(success, reason)` 双参）。
  - `endGame()` 的分支结构：当前是 `if(success){...}else{...}`，需改为三分支。**注意 `endGame` 被 6 处调用**（阵亡、超时、撤离完成、放弃行动等），改签名时必须逐一核对，避免漏改导致静默走进错误分支。
  - `renderResultLoot()` / 结算界面：新增「弃包撤离」标题样式与「丢失清单」区（与 FIX-17 的损失清单合并实现更省事）。
- **与 FIX-07 的关系**：**FIX-16 必须在 FIX-07 之前完成**。原因：FIX-07 的存活率假设（T1 45% / T2 60% / T3 80%）只有在「超时不算死」的前提下才成立——否则超时的 20 分钟末段会按阵亡计入损失，把实际存活率拉低约 3–8 个百分点，直接击穿 §5.2 的 0.53 下限。
- **验收判据**：
  1. 故意等到倒计时归零 → 结算标题显示**「弃包撤离」**，不是「行动失败」。
  2. 该局背包内的物品**不出现**在仓库。
  3. 该局安全箱内的物品**出现**在仓库。
  4. 该局口袋里放 3 个绷带 → 撤离后仓库多出 **3 个绷带**。
  5. 阵亡（被打死）→ 结算标题仍为「行动失败」，且口袋物品**丢失**（与超时区分开）。
  6. `rg "endGame\(false\)" game.js` 中不再包含超时路径。
- **优先级**：**P1**（但作为 FIX-07 的前置，实际执行顺序排在 B2 之前）

### FIX-17 ⚖️ 结算界面不显示损失清单

- **现象**：`renderResultLoot()` 只渲染**成功带出**的物品（从 `S._lootItems` 读）。阵亡 / 超时后这一栏为空，玩家看不到自己损失了价值多少的东西。搜打撤品类最重要的情绪反馈（「我丢了什么」）完全缺失。
- **目标值**：三种结局都显示**双栏**：

- **验收判据**：
  1. 带 ₵2,000,000 物资阵亡 → 结算界面显示「损失 ₵2,000,000」。
  2. 带 ₵2,000,000 物资超时 → 显示「保住 ₵X / 丢失 ₵Y」，且 X+Y ≈ 2,000,000。
  3. 空手撤离成功 → 「丢失」栏显示「无」而非空白或报错。
- **优先级**：**P2**（但与 FIX-16 同批实现最省事——两者都改 `endGame` 的结算段）

## 附：本文档的复算方法（供平衡回归）

所有期望值由以下步骤复算，任何人可重跑：

1. 从 `game.js` 按大括号配平提取 `ITEMS` / `SHOP_PRICES` / `CONTAINER_TYPES` 对象字面量。
2. 按 `game.js:770-835` 的合并逻辑补入收集品，**但执行 FIX-05（剔除 `africa_star`）与 FIX-06（替换为红藏品掷骰）**。
3. 单箱期望 = Σ(池内 `value` 均值 × 期望件数) + 红藏品掷骰期望 + 头奖掷骰期望。
4. 单局带出 = 按军事禁区容器配比（weaponBox 29/equipBox 29/ammoBox 29/supplyBox 29/safe 28/medBox 26）随机抽样 N 箱，按**价值密度（₵/kg）贪心装箱**，受 70kg 负重与背包格数双约束。蒙特卡洛 ≥ 3000 次。
5. `net = survival × gross − (1 − survival) × kitCost`；`raids = nextKitCost / net`。

> **建议固化为 `tests/balance-sim.js` 并纳入 CI**——本文档的所有数字都应能在一条命令后重现。当前这些计算是一次性脚本，未入库。
