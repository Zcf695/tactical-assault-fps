## 1. 设计目标

### 1.1 一句话目标

用一个箱子换玩家 **2 到 8 秒的紧张期待**，并且让这份期待与物品真实价值严格对应。

### 1.2 可测目标

| 编号 | 目标 | 判定方式 |
|------|------|----------|
| G-01 | 稀有度必须能被「感知」而不只是「看到」 | 玩家在物品浮出前，能通过音效与时长差异区分「这箱有货」与「这箱是垃圾」 |
| G-02 | 搜刮必须有机会成本 | 开箱期间玩家处于可被攻击的状态（揭示期不能开枪，`game.js:2795`） |
| G-03 | 每个容器都应值得打开 | 最差容器（弹药箱）单箱期望价值 > 0 且非零概率出现有用物品 |
| G-04 | 容器不是无限资源 | 每图容器数有限（170/86/78），单局无法全部清空（**当前未达成**，见 §6 B-05） |
| G-05 | 拾取必须受容量约束 | 格满或超重时必须有明确拦截，且不吞物品 |

### 1.3 不做什么

- ❌ 不做「一键搜刮整张地图」的自动化
- ❌ 不做搜刮小游戏（转盘、连线等）——本作的节奏点在「等待揭示」，不在交互技巧
- ❌ 不做容器刷新（每局重新生成，同一局内容器内容固定）

## 2. 核心循环

### 2.1 单次搜刮循环

```
[接近容器 ≤2.8m]
        ↓  显示提示框「{容器名} 按 F 搜索」
[按 F / interact()]
        ↓  进入 searching 阶段，释放鼠标，显示搜索界面
[逐件揭示：每件间隔 = f(稀有度)]
        ↓  每揭示一件播放对应档位音效
[玩家决定：拿 / 不拿 / 拖动整理]
        ↓
[ESC / 关闭 → 回到 playing，重新锁定鼠标]
```

### 2.2 局内搜刮循环

```
选择目标容器 → 移动 → 开箱 → 揭示 → 取舍（空间不足要丢东西）→ 下一个
     ↑                                                        │
     └──────────── 负重/格数接近上限时被迫回撤离点 ←──────────┘
```

> **设计意图**：容量压力应当逐步累积，最终迫使玩家「放弃剩余收益、回家」。这是本作事实上的核心张力（而非时间压力，详见 `03-core-loop.md` §3.4）。

### 2.3 节奏参数

| 阶段 | 时长 | 玩家状态 |
|------|------|----------|
| 接近 | 自由 | 可移动、可开枪 |
| 开箱瞬间 | **0s（无前摇）** | 立即失去开枪能力 |
| 揭示 | 每件 0.5 / 1.0 / 2.0 / 3.0 / 4.0s | 不能开枪，不能移动（鼠标已释放） |
| 取舍 | 自由 | 可拖拽、可丢弃、可关闭 |

### 3.2 输出（副作用）

| 输出 | 数据变化 | UI 变化 |
|------|----------|---------|
| 首次搜某容器 | `container.searched=true`；`S.containersSearched++`；`trackMission('search_containers',1)`；`gainXP(5)`；`trackAchievement('searches',1)` | 提示框追加「(已搜索)」 |
| 揭示一件 | `container._revealed[i]=true`；`container._revealCount=i+1` | 格子从 `unrevealed` 变为可见 |

| 放入容器 | 目标区数据变化 | 网格重绘 |

### 3.3 拾取的目标容器优先级（自动放置）

玩家**单击**物品时，`takeSearchItem` 按以下顺序尝试（`game.js:5922-5997`）：

| 序 | 目标 | 条件 | 备注 |
|----|------|------|------|
| 1 | **装备槽**（自动穿戴） | `def.type ∈ {armor, helmet, chestRig, backpack, weapon}` 且 `autoEquipLoot()` 成功 | 装备槽已占用则继续下一级 |
| 2 | **钥匙链** | `def.type === 'keycard'` 且有空格 | 同时设 `S.keyUses[i]=10` |
| 3 | **口袋** | 非 `valuable` 且 `S.pockets.length < S.maxPockets(5)` | 收藏品跳过此级 |
| 4 | **胸挂** | 非 `valuable` 且 `S._rigItems.length < chestRig.slots` | 收藏品跳过此级 |
| 5 | **背包** | `w×h` 能放下 | 收藏品从这一级开始 |
| 6 | **安全箱** | 背包放不下，`3×3` 内能放下 | |
| 7 | **失败** | 以上全部失败 | `alert('背包和安全箱都已满！')`，**物品留在容器内不消失** |

> ✅ 第 7 级行为正确：不是「静默丢弃」，物品仍可后续处理。这满足 G-05 的一半。
> 🔴 但**全流程无负重校验**（D-26）——G-05 的「超重」分支在主路径上根本不存在。

## 5. 状态机

### 5.1 容器状态

```
        ┌──────────────┐
        │  unsearched  │  容器生成时
        └──────┬───────┘
               │ 首次 openSearch()
               ▼
        ┌──────────────┐
        │   searched   │  searched=true（本局内不再变回）
        └──────┬───────┘
               │ items[i].taken = true
               ▼
        ┌──────────────┐
        │   emptied    │  所有 item.taken === true
        └──────────────┘
```

**注意**：`searched` 标记只影响 **XP/任务/成就是否计入**（`game.js:5325`），不影响能否再次打开。已搜过的容器可以反复打开整理。

### 5.2 物品状态（每件独立）

```
  [hidden] ──(计时到)──→ [revealed] ──(玩家拾取)──→ [taken]
```

`container._revealed[i]` 是唯一真值。`takeSearchItem` 有硬校验：`if(!container._revealed[idx]) return;`（`game.js:5919`）——**未揭示的物品无法被拾取，包括拖拽**。

### 5.3 游戏阶段状态机

```
   playing ──(F 邻近容器)──→ searching ──(关闭)──→ playing
      │                          │
      │                          └──(阵亡)──→ gameover
      └──(背包键)──→ backpack ──(关闭)──→ playing
```

- `searching` 期间：鼠标解锁（`document.exitPointerLock()`，`game.js:5324`）、显示丢弃区（`showDropZones(true)`）、`shoot()` 被拦截（`game.js:2795`）
- `searching` 期间**不暂停游戏世界**：敌人仍在移动、仍会射击。这是 G-02 的实现基础。

### 5.4 揭示定时器状态

| 变量 | 作用域 | 清理时机 |
|------|--------|----------|
| `searchRevealTimer` | 全局单例 | `clearSearchReveal()`：新开箱、关闭搜索、开箱中切换容器 |
| `searchAnimData` | 全局单例 | 已废弃（对应死掉的进度条路径） |

> 🟡 `searchRevealTimer` 是**单例**。若玩家在揭示过程中快速切换到另一个容器，前一个容器的揭示会被中断且**不会恢复**——该容器剩余物品永久停留在 `hidden` 状态，**无法拾取**。这是 §6 的 E-03。

## 6. 边界与异常

### 6.1 已识别边界情况

| ID | 场景 | 当前行为 | 判定 |
|----|------|----------|------|
| E-01 | 背包 + 安全箱全满时拾取 | `alert('背包和安全箱都已满！')`，`item.taken` 保持 `false`，物品留在容器 | ✅ 正确 |
| E-02 | 未揭示的物品被点击/拖拽 | `takeSearchItem` 首行校验 `_revealed[idx]`，直接 return | ✅ 正确 |

| E-05 | 揭示进行中按 ESC | `closeSearch()` → 定时器清理，物品保持 hidden | 🟡 可接受（重开箱子会重新揭示） |
| E-06 | 搜刮时超重 | **不拦截**（D-26） | 🔴 缺陷 |
| E-07 | 已搜过的容器再次打开 | `_revealed` 全 true → 跳过揭示，直接显示 | ✅ 正确 |
| E-08 | 容器内物品数 = 0 | `def.min ≥ 1`，理论上不会出现；`startItemReveal` 对空数组的 `firstItem` 有 `:300` 兜底 | ✅ 安全 |
| E-09 | 拾取时装备槽已有同类型装备 | `autoEquipLoot` 失败的物品会 fall through 到背包 | ✅ 正确 |
| E-10 | 容器生成时搜索网格放不下所有物品 | `if(slot) placeInGrid(...)` 静默跳过 → **实际件数可能少于 `cnt`**（`game.js:5042-5043`） | 🟡 静默少给，无提示 |
| E-11 | 幸运儿技能 + 池为空 | `sortedItems` 为空时 `Math.floor(Math.random()*0)` = 0，`topCount = max(1, 0) = 1`，`sortedItems[0]` = `undefined` → **生成一件 `undefined` 物品** | 🟡 理论风险，实际池永不为空 |
| E-12 | 同一容器被两个定时器同时揭示 | 单例定时器 + `S.currentSearchContainer!==container` 校验（`game.js:5348`） | ✅ 正确 |
