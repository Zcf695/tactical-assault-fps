## 1. 设计目标

### 1.1 一句话目标

让撤离成为**全游戏最紧张的 8 秒**——玩家在此刻同时承受「已经赚到了」的满足与「可能全丢」的恐惧。

### 1.2 可测目标

| 编号 | 目标 | 判定方式 |
|------|------|----------|
| G-01 | 撤离必须有明确的空间成本 | 从「最后搜刮点」到「最近撤离点」的距离应 ≥ 单局移动预算的 25% |
| G-02 | 撤离必须有时间紧迫感 | 局末 10% 时间内，玩家必须已经放弃继续搜刮 |
| G-03 | 撤离点状态必须可读 | 玩家在 50m 外就能看出哪个点开着 |
| G-04 | 撤离过程必须可中断 | 离开范围 → 进度归零（不是「暂停」） |
| G-05 | 死亡损失必须可预估且不可逆 | 阵亡瞬间就能确定「丢了什么」，无需等结算 |
| G-06 | 撤离成功与超时必须**显著不同** | 超时不应等同于阵亡 |

### 1.3 不做什么

- ❌ 不做多人争夺的撤离点
- ❌ 不做「撤离载具召唤」（描述里的「需要船只」是无实现的文案）
- ❌ 不做撤离读条中的 QTE
- ❌ 不做撤离后回溯（一旦撤离不可反悔）

## 2. 核心循环

### 2.1 撤离判定循环（每帧）

```
每帧 checkExtractZone():
  ├─ 找到最近的「已开启」撤离点
  ├─ 玩家在其半径 3.5m 内？
  │    ├─ 是 且 未在读条 → 显示提示「{名字} - 按 F 开始撤离」
  │    ├─ 是 且 在读条   → 进度继续累加
  │    └─ 否 且 在读条   → 读条取消，进度归零（不是暂停！）
  └─ 结束

每帧 updateExtract(dt):
  ├─ S.extractProgress += dt
  ├─ 高危模式：每 3s 惊动 40m 内的敌人
  └─ progress >= 8s → endGame(true)
```

### 2.2 完整撤离流程

```
[决定撤离]
    ↓
[查看指南针 / 全图，确认哪个点开着]   ← 8 个点，状态动态翻转
    ↓
[移动过去（可能 5m，也可能 293m）]
    ↓
[进入半径 3.5m → 提示出现]
    ↓
[按 F → startExtraction()]
    ↓
[站桩 8 秒，不能离开圈]  ← 高危模式下每 3s 惊动 40m 敌人
    ↓
[8 秒满 → endGame(true) → 装备/背包/安全箱全部入库，钱 += 战利品价值]
```

### 2.3 未撤离的两种结局

| 结局 | 触发 | 后果 |
|------|------|------|
| **阵亡** | `S.health <= 0` | 安全箱+钥匙链保留，其余全丢，XP = 0 |
| **超时** | `remain <= 0`（`game.js:7098`） | **与阵亡完全相同的分支** `endGame(false)` |

## 3. 输入输出

### 3.1 撤离点数据输入（`map/*.js` 的 `extracts`）

每张图 8 个，条目结构：`{x, z, name, desc}`。

**军事禁区 8 个撤离点**（`map/military_base.js:302-311`）：

| # | 名称 | 坐标 | 距出生点 | `desc` 声称的条件 | 实际校验 |
|---|------|------|----------|------------------|----------|
| 1 | 北撤离点 | (0, 145) | 280 m | 直升机坪，常规撤离 | 无 |
| 2 | 南撤离点 | (0, −145) | **10 m** | 跑道尽头，常规撤离 | 无 |
| 3 | 东撤离点 | (145, 0) | 198 m | 公路检查站，常规撤离 | 无 |
| 4 | 西撤离点 | (−145, 0) | 198 m | 边境通道，常规撤离 | 无 |
| 5 | 港口海路撤离 | (135, 75) | 250 m | **「需要船只」** | 🔴 **未校验** |
| 6 | 地下通道撤离 | (−135, −135) | 135 m | **「需要紫色钥匙卡」** | 🔴 **未校验** |
| 7 | 村庄小路撤离 | (135, −125) | 135 m | 「随机开启」 | ✅ 由 `isOpen` 实现 |
| 8 | 发电站铁路撤离 | (−135, 125) | **293 m** | 「等待列车」 | 🔴 未校验 |

> 🔴 **所有 `desc` 里的条件都是纯文案。** `checkExtractZone` 只检查 `ep.isOpen`（`game.js:6872`），**不检查钥匙卡、不检查船只、不检查列车**。玩家不带任何钥匙卡也能从「地下通道撤离」离开。

### 3.2 玩家输入

| 输入 | 条件 | 处理 |
|------|------|------|
| `F` 键 | 在已开启撤离点的 3.5m 内 且 `!S.isExtracting` | `startExtraction()`（`game.js:6890`） |
| 移动出圈 | `S.isExtracting === true` | `checkExtractZone` 中 `S.isExtracting=false; S.extractProgress=0`（`game.js:6886`） |

> 🟡 `F` 键是**多用途键**：`interact()` 按以下优先级分派（`game.js:5260-5295`）：
> 1. BOSS 任务点 → 2. 空投 → 3. 容器（2.8m）→ 4. 地面物资 → 5. 钥匙房 → 6. 撤离点
>
> 因此**若撤离点附近 2.8m 内有容器，按 F 会先去开箱子，无法撤离**。设计上应避免在撤离点附近放容器。

### 3.3 输出

| 输出 | 数据 | UI |
|------|------|-----|
| 开始读条 | `S.isExtracting=true; S.extractProgress=0` | 进度条显示，标题变「撤离中...」 |
| 每帧进度 | `S.extractProgress += dt` | `#extractProgressFill` 宽度 = `progress/8 × 100%` |
| 每秒 | — | `sfxExtractTick()` 滴答声 |
| 高危每 3s | `alertEnemies(playerPos, 40)` | 附近敌人转 `chase` |
| 完成 | `endGame(true)` | 结算界面「撤离成功」 |
| 撤离点翻转 | `ep.isOpen = !ep.isOpen` | 全局提示「✅ X 撤离点已开放 / ❌ 已关闭」+ 3D 颜色变化 |

**占空比推算**：

| 起点 | 开启时长均值 | 关闭时长均值 | 开启占空比 |
|------|-------------|-------------|-----------|
| 初始开启 | 120 s | 70 s | 63% |

→ 任意时刻**期望开启数 ≈ 5.4 / 8**。

### 4.3 撤离距离矩阵

> 有效移速：走 8 m/s；冲刺 13.2 m/s（8 × 1.65）；体力 100 消耗 30/s → 冲刺 3.33s；回复 18/s → 5.5s 充满。**冲刺循环的有效均速 ≈ 10 m/s。**

**军事禁区**（出生点 0, −135）：

| 撤离点 | 距离 | 纯移动耗时 | 占 1200s 局时长 |
|--------|------|-----------|----------------|
| 南撤离点 | **10 m** | **1.0 s** | **0.08%** |
| 地下通道 / 村庄小路 | 135 m | 13.5 s | 1.1% |
| 东 / 西撤离点 | 198 m | 19.8 s | 1.7% |
| 港口海路 | 250 m | 25.0 s | 2.1% |
| 北撤离点 | 280 m | 28.0 s | 2.3% |
| 发电站铁路 | **293 m** | **29.3 s** | **2.4%** |

**密林前哨**（出生点 0, −130）：最近 **5 m**（南撤离点），最远 265 m（北撤离点）。
**工业港**（出生点 0, −130）：最近 **5 m**（南撤离点），最远 265 m（北撤离点）。

> 🔴 **G-01 严重未达成**：最远的撤离点也只需 **29 秒**，占单局 1200 秒的 **2.4%**。而最近的撤离点距离出生点只有 **5–10 米**。
>
> 这意味着「撤离」在本作中**不构成任何空间成本**。搜打撤品类最核心的张力——「必须带着战利品穿越危险区才能兑现」——在数值上被彻底消解。

### 4.5 死亡损失规则（`endGame`）

| 类别 | 撤离成功 | 阵亡 | 超时 |
|------|----------|------|------|
| 资金 | `+= S.lootValue` | 不变 | 不变 |
| 安全箱内物品 | → 仓库/邮箱 | **→ 仓库/邮箱** | **→ 仓库/邮箱** |
| 钥匙链 | 保留（含使用次数） | **保留** | **保留** |
| 武器（3 槽） | → 仓库/邮箱 | 丢失 | 丢失 |
| 护甲 / 头盔 / 胸挂 / 背包 | → 仓库/邮箱 | 丢失 | 丢失 |
| 背包内物品 | → 仓库/邮箱 | 丢失 | 丢失 |
| **口袋内物品** | 🔴 **消失（未迁移）** | 丢失 | 丢失 |
| **胸挂内物品** | 🔴 **消失（未迁移）** | 丢失 | 丢失 |
| XP | `50 + lootValue × 0.1` | 0 | 0 |
| 任务 `extract_success` | +1 | — | — |
| 成就 `extracts` | +1 | — | — |

> 🔴 **D-28**：`endGame(true)` 迁移了武器（`game.js:10037`）、装备（`10038`）、背包（`10039`）、安全箱（`10040`），**但没有迁移 `S.pockets` 与 `S._rigItems`**，随后在 `game.js:10049` 直接清空。
>
> **受影响范围（精确版）**：
> - 自动拾取时，收藏品（`type:'valuable'`）会**跳过**口袋与胸挂（`game.js:5962-5992`），所以大红不会自动进这里；
> - 但**医疗品、弹药、投掷物会自动进**口袋/胸挂（优先级 3、4）→ 这些必丢；
> - 玩家**手动拖拽**时，`canItemFitZone` 允许任意非装备类物品进入 pocket/rig（`game.js:8746-8756`），**收藏品也可以拖进去** → 手动放置的贵重品也会丢。
>
> 净效果：每次成功撤离都会静默吞掉玩家的药品、弹药，以及他手动塞进口袋的任何东西。

### 4.6 结算数值

| 项 | 公式 | 例（带出 ₵5,000,000） |
|----|------|---------------------|
| 资金 | `P.money += lootValue` | +₵5,000,000 |
| XP | `50 + floor(lootValue × 0.1)` | **500,050 XP** |
| 升级 | `level = floor(xp / 1000) + 1` | 直接从 1 级跳到 501 级 |
| 每级奖励 | `+₵5,000`、`+1 技能点` | — |

> 🔴 **XP 与资金完全脱钩于等级系统**。`lootValue` 量级是数百万，`×0.1` 后仍是数十万 XP，而 `XP_PER_LEVEL = 1000`（`game.js:4292`）。
> **一次成功撤离即可从 1 级直接升到数百级**，获得数百技能点（18 个技能满点只需 3×(5×3+3) = 54 点）。
>
> 这意味着：等级系统、技能树、成就的等级分支**全部在第一次撤离后失效**。
> 注：`gainXP` 在 `game.js:4314-4322` 只处理**一次**升级（`if (newLevel > oldLevel)` 只 +1 技能点 +₵5,000），因此实际是「跳级但只发 1 次奖励」。无论哪种解释，等级曲线都已断裂。

## 5. 状态机

### 5.1 撤离点状态

```
        ┌──────────┐   openTimer ≤ 0    ┌──────────┐
        │  开启     │ ────────────────→ │  关闭     │
        │ isOpen=T │ ←──────────────── │ isOpen=F │
        └──────────┘   openTimer ≤ 0    └──────────┘
             │                                │
             │ 计时器重置 90–210s              │ 计时器重置 40–100s
             └────────────────────────────────┘

  视觉：开启 = 绿环 + 绿色光柱 + 绿色标签
       关闭 = 灰环 + 灰色光柱（透明度降到 0.2）
```

### 5.2 撤离读条状态

```
   [idle]  ──F 且 inZone──→  [extracting]
                                  │
              ┌───────────────────┼───────────────────┐
              │                   │                   │
        离开半径              玩家阵亡            progress ≥ 8s
              │                   │                   │
              ▼                   ▼                   ▼
          [idle]（归零）      [gameover]        [撤离成功]
```

| 状态 | 变量 | 可否被中断 |
|------|------|-----------|
| `idle` | `S.isExtracting = false` | — |
| `extracting` | `S.isExtracting = true`，`S.extractProgress` 累加 | ✅ 离开半径立即归零 |

> **注意**：`extracting` 中**玩家仍可移动、射击、切换武器、搜刮**——`updateExtract` 不锁定任何输入。唯一的约束是「不能出圈」。

### 5.3 结算状态

```
   playing ──(撤离完成)──→ gameover（title=撤离成功）
      │
      ├──(HP ≤ 0)──────→ gameover（title=行动失败 / 阵亡）
      └──(倒计时归零)──→ gameover（title=行动失败 / 阵亡）
```

> ⚠️ **三条路径只有两种结局**。超时与阵亡走同一个 `endGame(false)`，结算标题、损失规则、XP 完全相同（`game.js:10051-10065`）。

## 6. 边界与异常

| ID | 场景 | 当前行为 | 判定 |
|----|------|----------|------|
| E-01 | 8 个撤离点全部关闭 | 最长等 90s，之后必然有开启 | ✅ 无死锁（概率 0.066%） |
| E-02 | 读条中离开半径 | 进度归零（不是暂停） | ✅ 符合 G-04 |
| E-03 | 读条中受伤 | **继续读条，不打断** | 🟡 高危模式 8 秒无伤几乎不可能，可能是缺陷 |

| E-06 | 在撤离点旁边有容器 | `F` 优先开箱子，无法撤离 | 🟡 见 §3.2 |
| E-07 | 站在关闭的撤离点上按 F | `checkExtractZone` 用 `if(!ep.isOpen)continue` 过滤 → 无提示、无反应 | ✅ 但无「此点已关闭」反馈 |
| E-08 | 不带钥匙卡走「地下通道撤离」 | **可以撤离**（描述是纯文案） | 🔴 D-17 |
| E-09 | 撤离时口袋/胸挂有物品 | **物品消失** | 🔴 D-28 |
| E-10 | 撤离成功但仓库已满 | `stashOrMail` 溢出到 `P.mailItems`（无上限） | ✅ 安全 |
| E-11 | 超时 | 与阵亡完全相同 | 🔴 见 §4.5 |
| E-12 | 全图容器搜完但仍有余时 | 玩家可以干等到倒计时（无事可做） | 🟡 无「提前撤离」激励 |
