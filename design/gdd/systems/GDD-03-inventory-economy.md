## 1. 设计目标

### 1.1 一句话目标

让「整理背包」本身成为一种乐趣，并让「装不下」成为玩家离开地图的真实理由。

### 1.2 可测目标

| 编号 | 目标 | 判定方式 |
|------|------|----------|
| G-01 | 背包是形状游戏，不是计数游戏 | 2×2 的物品必须能找到「非等价的替代摆放」，且玩家有动机调整布局 |
| G-02 | 容量压力必须在单局内被感知 | 玩家在中后期的某时刻必然遇到「装不下」并被迫取舍 |
| G-03 | 死亡损失必须可预估 | 玩家能事先知道「哪些一定保住、哪些一定丢」 |
| G-04 | 仓库必须构成长期目标 | 仓库/负重扩容应需要数局积累 |
| G-05 | 经济必须有约束力 | 至少存在一类物品，玩家需要「攒几局」才能买 |
| G-06 | 交易必须双向可用 | 任意 `ITEMS` 中的物品都能买入与卖出 |

### 1.3 不做什么

- ❌ 不做玩家间交易 / 拍卖行（需后端）
- ❌ 不做动态定价 / 供需模型
- ❌ 不做装备绑定 / 耐久继承到交易（武器耐久是全局按 key 存的）
- ❌ 不做负重影响移动（只有拾取拦截）

## 2. 核心循环

### 2.1 局内背包循环

```
搜到物品 → 自动/手动放置 → 空间不足 → 整理（旋转、挪位、丢弃）→ 继续
                │                                              │
                └──────── 安全箱优先（死了也带走）←─────────────┘
```

### 2.2 局外经济循环

```
撤离带出 → 仓库/邮箱 → 卖出换钱 → 买入更好的装备 → 下一局
                │
                └→ 提交材料 → 升级负重/仓库上限 → 能带更多 → 下一局收益更高
```

### 2.3 容量层级（六层，从「必保」到「必丢」）

| 层 | 容器 | 容量 | 死亡时 | 说明 |
|----|------|------|--------|------|
| 1 | 装备槽（甲/盔/胸挂/背包） | 4 槽 | **丢失** | 决定护甲与容量 |
| 2 | 武器槽 | 3 + 匕首 | **丢失** | 主 1 / 主 2 / 副 |
| 3 | 背包（随背包物品变化） | 4 – 56 格 | **丢失** | 主战利品区 |
| 4 | 胸挂 `_rigItems` | 1 – 10 格 | **丢失** | 快速取用区 |
| 5 | 口袋 | 5 格 | **丢失** | 医疗/弹药优先 |
| 6 | **安全箱** | **9 格（3×3）** | **保留** | 死亡保险 |
| 7 | **钥匙链** | **4 格 × 10 次** | **保留** | 仅钥匙卡 |

> ⚠️ 层 1–5 死亡全丢，层 6–7 死亡保留。这是 G-03 的全部内容，**游戏内没有任何界面告诉玩家这件事**。

## 3. 输入输出

### 3.1 网格系统接口（`game.js:849-1047`）

| 函数 | 签名 | 作用 |
|------|------|------|
| `initGrid(rows)` | → `{_items:[], rows}` | 创建行数为 rows 的空网格 |
| `canPlaceInGrid(grid, cols, itemId, col, row, excludeEntry)` | → bool | 检测能否放下（含旋转？见下注） |
| `placeInGrid(grid, cols, itemId, col, row)` | → entry | 放置并返回条目 |
| `removeFromGrid(grid, entry)` | → void | 移除 |
| `findFreeSlot(grid, cols, maxRows, itemId)` | → `{col,row}` \| null | 找一个能放下 `w×h` 的空位 |
| `countGridItems(grid)` / `gridIsEmpty(grid)` | → number / bool | 统计 |
| `moveGridItem(grid, cols, maxRows, entry, newCol, newRow)` | → bool | 移动 |
| `autoSortGrid(grid, cols, maxRows)` | → void | 自动整理（按面积降序重排） |
| `takeContainerItem(container, item)` | → void | 从容器移除并标记 `taken` |

> 🔴 **D-27 物品旋转未实现（已确证）**：`canPlaceInGrid`（`game.js:849-861`）严格使用 `def.w` 与 `def.h` 原值，**全代码库不存在任何旋转函数**（`rotate`/`rotated`/`swap(w,h)` 均无匹配，`game.js:7167` 的 `rotate` 是伤害方向指示器的 CSS 变换，与物品无关）。物品条目结构 `{id, col, row}` 也不存朝向（`game.js:866`）。
> 因此 README:43 的「tetris-style 拖拽背包」**不成立**——没有旋转就没有 Tetris，只有「矩形装箱」。这是支柱一（形状深度）与 README 宣传的共同缺口，需主理人裁定：补实现旋转，还是修改宣传口径。

### 3.3 经济输入输出

| 操作 | 函数 | 前置校验 | 失败反馈 |
|------|------|----------|----------|
| 买入 | `buyItem(itemId)` | `SHOP_PRICES[id]` 存在 且 `P.money >= buy` 且 仓库有空间 | `alert('仓库空间不足！')` 或静默 return |
| 卖出 | `sellItem(itemId)` | 仓库中确实有该物品 | 静默 return |

| 仓库升级 | `doUpgradeStash()` | 达到 `STASH_UPGRADES[lv-1]` 的资金与材料 | 按钮 disabled |
| 邮件领取 | `claimMailItem(idx)` | 仓库有空间 | `alert('仓库空间不足！')` |

> 🔴 买入失败（钱不足）时 `buyItem` 直接 `return false`，**无任何提示**（`game.js:6924`）。玩家点了没反应。

## 5. 状态机

### 5.1 物品生命周期

```
  [未生成] → [掉落在容器/地面] → [已拾取]
                                    │
                    ┌───────────────┼──────────────┬─────────────┐
                    ▼               ▼              ▼             ▼
              [装备槽]        [背包/安全箱]    [口袋/胸挂]    [钥匙链]
                    │               │              │             │
              撤离→仓库      撤离→仓库       撤离→仓库      保留(不存档?
              阵亡→丢失      阵亡→安全箱保留  阵亡→丢失      阵亡→保留)
                    │               │              │
                    └───────────────┴──────────────┘
                                    ▼
                            [仓库] → 卖出 → [消失]
```

> 🟡 **口袋里和胸挂里的物品在撤离后去向未在代码中确认**。`endGame(true)` 迁移了武器（`weaponSlots`）、装备（`equipment`）、背包（`backpack._items`）、安全箱（`secureContainer._items`）（`game.js:10037-10040`），但**没有迁移 `S.pockets` 与 `S._rigItems`**。然后 `S.pockets=[]` / `S._rigItems=[]` 被清空（`game.js:10049`）。**口袋里和胸挂里的东西在撤离后凭空消失。**

### 5.2 网格条目状态

```
  [空] ←removeFromGrid─ [已放置] ─moveGridItem→ [已放置(新位)]
                          │
                     removeFromGrid → [空]
```

条目结构：`{id, col, row, _keyUses?}`。**不存 w/h**——w/h 每次从 `ITEMS[id]` 现查。这意味着**修改物品尺寸会破坏所有已有存档的布局**。

### 5.3 阶段状态（局内背包）

```
  playing ──(Tab/B)──→ backpack ──(Tab/B/ESC)──→ playing
      │                    │
      │                    └──(阵亡)──→ gameover
      └──(F 容器)──→ searching ──→ playing
```

`backpack` 阶段：鼠标解锁、`showDropZones(true)`、显示丢弃区。
